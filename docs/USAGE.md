# Подробное руководство пользователя: MimicType

## 1. Принцип работы

В отличие от стандартных автокликеров (`xdotool`, `wtype`), использующих синтетические события X11 (XTEST) или Wayland-протоколы, `mimictype` создаёт виртуальную USB-клавиатуру на уровне ядра через `/dev/uinput`:

```
mimictype -> /dev/uinput -> ядро Linux -> libinput -> композитор (KWin) -> окно (Chrome)
```

### Преимущества:
* **`event.isTrusted: true`**: Браузеры (Chrome, Firefox) обрабатывают события как ввод с физического контроллера.
* **Сохранение фокуса**: Утилита отправляет события в системную шину ввода; фокус активного окна не перехватывается и не нарушается.
* **Keystroke Dynamics**:
  * Логнормальное распределение времени удержания клавиши (*Dwell Time*).
  * Биомеханическое время перехода (*Flight Time*) для диграфов с учётом физического расстояния на клавиатуре.
  * Адаптивные когнитивные паузы перед знаками препинания, переводами строк и синтаксическими блоками кода.
  * Симуляция случайных опечаток по соседним клавишам (*Fat-finger*) с моторной инерцией и автоматическим откатом через `Backspace`.

## 2. Настройка окружения и прав доступа

Для генерации событий виртуальной клавиатуры без `sudo` пользователю требуется доступ к `/dev/uinput`.

### Добавление в группу input:
```bash
sudo usermod -aG input $USER
```

### Настройка udev-правила (если требуется):
Создайте файл `/etc/udev/rules.d/99-uinput.rules`:
```udev
KERNEL=="uinput", MODE="0660", GROUP="input", OPTIONS+="static_node=uinput"
```
Примените правила:
```bash
sudo udevadm control --reload-rules && sudo udevadm trigger
```

## 4. Режимы использования

### 4.1. Прямой режим (CLI с таймером)

При запуске без аргументов текст автоматически считывается из буфера обмена:
```bash
mimictype
```
По умолчанию запускается 3-секундный таймер обратного отсчёта, за время которого нужно кликнуть в целевое окно.

#### Дополнительные параметры:
```bash
# Задержка 5 секунд и скорость 120 WPM
mimictype -d 5 -w 120

# Ввод конкретной строки
mimictype "Hello, World!" -d 2

# Ввод из файла или конвейера (stdin)
cat script.py | mimictype --stdin -d 3

# Отключение симуляции опечаток
mimictype --no-humanizer
```

---

### 4.2. Фоновый демон с глобальным хоткеем

Запуск фонового процесса:
```bash
mimictype daemon --hotkey ctrl+alt+v
```

#### Порядок работы:
1. Выделите и скопируйте любой текст (`Ctrl+C`).
2. Поставьте курсор в нужное поле ввода (в браузере, терминале или текстовом редакторе).
3. Нажмите комбинацию **`Ctrl+Alt+V`**.
4. Ввод начнётся без изменения фокуса окна.

---

### 4.3. Управление через IPC (сокет)

Когда демон запущен, им можно управлять из других скриптов, терминалов или горячих клавиш оконного менеджера (KDE / GNOME / i3 / niri):

```bash
# Начать ввод текущего содержимого буфера обмена
mimictype trigger

# Начать ввод произвольного текста
mimictype trigger "Текст для быстрой вставки"

# Проверить состояние демона
mimictype status

# Экстренно остановить набор
mimictype stop
```

## 5. Пресеты скорости и тонкая настройка

Утилита поддерживает готовые профили динамики печати (`--preset`):

| Пресет | Скорость (WPM) | Частота опечаток | Описание |
|---|---|---|---|
| `natural` (по умолчанию) | 65 | 2.0% | Естественный человеческий темп, паузы осмысления |
| `fast` | 100 | 0.8% | Уверенный быстрый набор, короткие паузы |
| `careful` | 45 | 3.0% | Вдумчивый набор с увеличенными паузами |
| `instant` | 300+ | 0% | Максимально быстрый машинный ввод |

Пример использования:
```bash
mimictype --preset fast
```

Пользовательские настройки можно сохранить в YAML-файл и передавать через флаг `-c / --config`.

## 6. Аварийное прерывание (Kill Switch)

В процессе набора на любой физической клавиатуре доступен аварийный выключатель:
* Нажатие клавиши **`ESC`** мгновенно прерывает выполнение, сбрасывает все зажатые модификаторы (`Shift`, `Alt`, `Ctrl`) и возвращает систему в исходное состояние.
* В терминале аналогично действует комбинация **`Ctrl+C`**.

## 7. Интеграция с oes-babl и Xephyr

В проекте `oes-babl` Chrome запускается на изолированном X-экране Xephyr:
* `mimictype` передаёт события на уровне ядра. Композитор Wayland (KWin) перенаправляет их в активное окно Xephyr, а Xephyr передаёт события в браузер.
* Для буфера обмена поддерживаются как нативный Wayland (`wl-paste`), так и гостевой X11 (`xclip`).
* Переключение раскладок между английским и русским текстом выполняется автоматически.

## 8. Верификация нативности ввода (DOM)

В репозиторий включена интерактивная страница для проверки параметров ввода:
```bash
google-chrome examples/verify_browser.html
```

Она отображает:
* Долю нативных событий `event.isTrusted: true` (должно быть 100%).
* Реальную скорость WPM и график задержек Dwell / Flight.
* Живой поток вводимых символов с визуализацией исправлений опечаток (`Backspace`).
